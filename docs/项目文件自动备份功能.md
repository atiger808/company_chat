# 项目文件自动备份功能

## 一、背景与目标

为防止项目文件因误操作、硬件故障或人为删除导致丢失，我们在局域网内搭建了一套**自动增量备份系统**。核心目标如下：

- **自动同步**：源服务器项目文件定时同步到备份服务器。
- **防误删**：源服务器删除文件时，备份服务器保留历史文件，不跟随删除。
- **保留历史**：备份服务器保留最近 3 次快照，可随时恢复到任意历史版本。
- **免密高效**：使用 SSH 免密登录与 rsync 增量传输，无需人工干预。
- **日志可查**：所有操作记录日志，便于排查问题。

---

## 二、整体架构

| 角色       | 服务器 IP     | 作用                               |
| ---------- | ------------- | ---------------------------------- |
| 源服务器   | 192.168.1.130 | 存放项目代码，运行 rsync 同步脚本  |
| 备份服务器 | 192.168.1.122 | 接收同步文件，创建快照并清理旧快照 |

**数据流向：**

```
源服务器项目目录 → rsync 增量同步 → 备份服务器 current 目录 → 硬链接快照 → 保留最近 3 个快照
```

**备份服务器目录结构：**
```
/www/backup/project/
├── current/               # 最新同步的项目文件（只增不减）
├── snapshot_20260908/     # 历史快照（硬链接，共享文件）
├── snapshot_20260909/
└── snapshot_20260910/     # 保留最近 3 个，旧的自动删除
```

## 三、关键配置与脚本

### 1. SSH 免密登录
在源服务器生成密钥并复制到备份服务器，实现 `rsync` 和 `ssh` 无需输入密码。

```bash
ssh-keygen -t ed25519
ssh-copy-id -p 22 root@192.168.1.122
```

### 2. 源服务器同步脚本：`/root/rsync_to_backup.sh`

**核心逻辑：**
- 使用 `rsync -avz --partial` 增量同步。
- **不使用 `--delete`**，确保备份端文件只增不减。
- 排除日志、缓存、`node_modules` 等无用文件。
- 输出日志到 `/var/log/rsync_backup.log`。

**关键命令片段：**

```bash
#!/bin/bash
# =============================================
# 源服务器：rsync 增量同步到备份服务器
# 特点：
#   1. 不删除备份端文件（无 --delete），防止误删同步
#   2. 使用 SSH 免密登录，无需输入密码
#   3. 排除临时文件、缓存、日志等无用文件
#   4. 输出详细日志，便于排查
# =============================================

# ---------- 配置变量 ----------
PROJECT_DIR="/www/yue/company_chat"      # 本地项目路径（末尾不加斜杠）
BACKUP_SERVER="192.168.1.122"                # 备份服务器 IP
BACKUP_USER="root"                           # 备份服务器用户名
BACKUP_PORT="22"                             # 备份服务器 SSH 端口
REMOTE_CURRENT="/www/backup/project/current" # 远程 current 目录

# ---------- 日志文件 ----------
LOG_FILE="/var/log/rsync_backup.log"

# ---------- 需要排除的文件/目录（按需增减） ----------
EXCLUDES=(
    "--exclude=.git/logs/"
    "--exclude=*.log"
    "--exclude=*.tmp"
    "--exclude=*.swp"
    "--exclude=.DS_Store"
    "--exclude=node_modules/"
    "--exclude=runtime/"
    "--exclude=cache/"
)

# ---------- 开始执行 ----------
echo "========================================" >> ${LOG_FILE}
echo "$(date '+%Y-%m-%d %H:%M:%S') - 开始 rsync 同步" >> ${LOG_FILE}

# ---------- 执行 rsync 同步 ----------
# 参数说明：
#   -a        归档模式（保留权限、时间、软硬链接等）
#   -v        详细输出
#   -z        传输时压缩
#   --partial 断点续传（网络中断后可继续）
#   -e        指定 ssh 端口
#   注意：这里刻意不使用 --delete，保证备份端文件只增不减
rsync -avz --partial \
    -e "ssh -p ${BACKUP_PORT}" \
    "${EXCLUDES[@]}" \
    ${PROJECT_DIR}/ ${BACKUP_USER}@${BACKUP_SERVER}:${REMOTE_CURRENT}/ >> ${LOG_FILE} 2>&1

# ---------- 结果判断 ----------
if [ $? -eq 0 ]; then
    echo "$(date '+%Y-%m-%d %H:%M:%S') - rsync 同步成功" >> ${LOG_FILE}
else
    echo "$(date '+%Y-%m-%d %H:%M:%S') - rsync 同步失败，请检查日志" >> ${LOG_FILE}
    exit 1
fi

echo "$(date '+%Y-%m-%d %H:%M:%S') - 同步任务结束" >> ${LOG_FILE}
```

### 3. 备份服务器清理脚本：`/root/cleanup_snapshots.sh`

**核心逻辑：**
- 将 `current/` 硬链接为当天的快照 `snapshot_YYYYMMDD`。
- 按名称排序，只保留最近 3 个快照，删除更旧的。
- 日志输出到 `/var/log/cleanup_snapshots.log`。

**关键命令片段：**

```bash
#!/bin/bash
# =============================================
# 备份服务器：创建快照并清理旧快照，保留最近 3 个
# =============================================

BASE_DIR="/www/backup/project"
KEEP_COUNT=3
LOG_FILE="/var/log/cleanup_snapshots.log"

echo "========================================" >> ${LOG_FILE}
echo "$(date '+%Y-%m-%d %H:%M:%S') - 开始创建快照并清理" >> ${LOG_FILE}

cd ${BASE_DIR} || {
    echo "$(date '+%Y-%m-%d %H:%M:%S') - 无法进入目录 ${BASE_DIR}" >> ${LOG_FILE}
    exit 1
}

# 1. 如果 current 不存在，创建空目录
[ -d current ] || mkdir -p current

# 2. 创建当天快照（硬链接 current 到 snapshot_YYYYMMDD）
DATE=$(date +%Y%m%d)
SNAPSHOT_DIR="${BASE_DIR}/snapshot_${DATE}"

rm -rf ${SNAPSHOT_DIR}
cp -al current ${SNAPSHOT_DIR} >> ${LOG_FILE} 2>&1

# 3. 删除超过保留数量的旧快照
ls -d snapshot_* 2>/dev/null | sort | head -n -${KEEP_COUNT} | xargs -r rm -rf >> ${LOG_FILE} 2>&1

echo "$(date '+%Y-%m-%d %H:%M:%S') - 清理完成，保留最近 ${KEEP_COUNT} 个快照" >> ${LOG_FILE}
```

### 4. 宝塔计划任务

| 服务器     | 任务名称          | 执行周期   | 脚本内容                     |
| ---------- | ----------------- | ---------- | ---------------------------- |
| 源服务器   | rsync_backup      | 每天 02:00 | `/root/rsync_to_backup.sh`   |
| 备份服务器 | cleanup_snapshots | 每天 02:30 | `/root/cleanup_snapshots.sh` |

> 备份服务器任务比源服务器晚 30 分钟，确保同步完成后再创建快照。

## 四、功能特点与优势

| 特性         | 说明                                       |
| ------------ | ------------------------------------------ |
| **增量同步** | 仅传输变化文件，节省带宽与时间             |
| **防误删**   | 源端删除文件，备份端保留，可随时恢复       |
| **历史快照** | 硬链接技术，多个快照共享文件，节省磁盘空间 |
| **自动清理** | 只保留最近 3 个快照，避免磁盘占满          |
| **免密操作** | SSH 密钥认证，无需人工输入密码             |
| **日志完善** | 所有操作记录日志，便于审计与排错           |
| **失败可察** | 脚本失败返回非 0，宝塔任务标记失败         |

## 五、恢复方式

若需恢复文件，有两种方式：

1. **从最新备份恢复**：直接拷贝 `/www/backup/project/current/` 中对应文件。
2. **从历史快照恢复**：进入 `/www/backup/project/snapshot_YYYYMMDD/`，找到所需版本文件拷贝回源服务器。

> 例如恢复 2026-09-08 的版本：
> ```bash
> cp /www/backup/project/snapshot_20260908/某文件 /www/yue/company_chat/某文件
> ```

## 六、日常维护与检查

1. **检查日志**：
   ```bash
   tail -f /var/log/rsync_backup.log
   tail -f /var/log/cleanup_snapshots.log
   ```
2. **查看备份目录**：
   ```bash
   ls -lh /www/backup/project/
   ```
   应看到 `current/` 和最近 3 个 `snapshot_*` 目录。
3. **验证同步**：在源服务器新增/删除文件，手动执行同步脚本，观察备份端变化（新增会同步，删除不会同步）。
4. **日志轮转**：已配置 `logrotate`，每周轮转，保留 4 周，避免日志过大。

## 七、注意事项

- **SSH 端口**：若备份服务器 SSH 端口非 22，需在脚本中同步修改 `-p` 参数。
- **硬链接限制**：`current/` 与 `snapshot_*` 必须在同一分区，否则 `cp -al` 会失败。
- **权限**：确保脚本有权限读写项目目录和日志文件。
- **磁盘空间**：虽采用硬链接节省空间，但仍需定期检查备份服务器磁盘使用情况。
- **首次运行**：首次执行清理脚本时，`current/` 可能为空，脚本已做容错处理。

## 八、总结

本备份方案实现了**自动化、增量、防误删、保留历史快照**的项目文件保护机制。通过源服务器与备份服务器的分工协作，配合宝塔计划任务，做到了“一次配置，长期无忧”。项目负责人及团队成员可通过日志随时了解备份状态，必要时可快速从历史快照中恢复文件，有效降低了数据丢失风险。

如需进一步扩展（如数据库备份、异地备份、邮件告警等），可在现有基础上叠加，不影响当前流程。
