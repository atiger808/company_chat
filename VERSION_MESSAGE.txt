3. OA审批：修复「切换审批类型后提交，金额与表单金额不一致」（隐藏 bug）：
   1）现象：新建审批时先选了某个类型（如内置报销）并填了金额，没提交就切换到另一个类型（如自定义的付款申请单）填完提交 —— 上一个类型残留的金额被一起提交，导致审批记录上的「金额」与表单里填的金额对不上；
   2）根因有两层：① 前端切换类型时只隐藏了上一个类型的内置表单，**没有清空已填的值**（金额/标题/日期/事由/附件/发票/动态表单等），提交时仍会把隐藏输入框里的旧值读出来；② 后端对「自定义类型 / 带表单的内置类型」直接把前端传来的 amount 存进审批记录的金额字段（只有物资三类单据额外从 form_data 同步），前端一旦带错就照单全收；
   3）前端修复：切换审批类型（点击类型卡片且类型确实变化）时**清空上一个类型填过的全部内容**——内置字段（标题/金额/日期/时数/事由/费用类型/招聘表单）、附件、发票、动态表单容器及其外挂状态（附件字段/人员字段/关联单/当前 schema）、审批链与抄送人，并重新按新类型带出默认值；点的是「当前同一个类型」或程序化设置类型（打开弹窗自动选中、编辑/驳回续审回填）都不会清空，不会影响重新编辑；
   4）后端修复（防呆、单一口径）：除「报销/采购/出差」外，审批金额**一律取该类型 schema 里的金额字段**在表单中的值（优先 key=amount，其次第一个 type=amount 的顶层字段，例如入库单取 actual_amount），**不再采信前端传来的 amount**；前端提交时也只在这两个类型才提交内置金额。连带修正：入库单之前按 `form_data['amount']` 同步（而它的字段叫 actual_amount，实际从未生效），现在也能正确镜像到审批金额；金额阈值（决定走哪条审批链）同样不再采用残留金额；
   5）存量数据：新增 `python manage.py backfill_approval_amount [--dry-run]`，把历史不一致的审批记录按上述口径改回与表单金额一致（幂等可重复执行；报销/采购/出差不动，表单没填金额的置空）。
4. 考勤打卡：修复「首次打开偶发『百度地图初始化失败：undefined is not a constructor』」（稍后又正常）：
   1）原因：百度地图是**分模块加载**的——`window.BMap` 会先被创建成一个**空壳**（此时 `BMap.Map` 还不存在），真正的 Map/Point 等构造函数随后才注册进来。而原来的「是否就绪」判断只看 `window.BMap` 是否存在，于是紧接着 `new NS.Map(...)` 就抛 `undefined is not a constructor`；等模块注册完（或再点一次「重新定位」）就又正常了——这正好对应「首次打开报错、之后正常」；
   2）修复①（根因）：就绪判断改为**必须确认核心构造函数已注册**（`BMap.Map` 与 `BMap.Point` 都是函数才算就绪），半加载状态一律视为「还没好」，继续走原来的轮询等待，不再抢跑；
   3）修复②（兜底）：两处初始化/绘制都新增「半加载错误」识别（`undefined is not a constructor` / `is not a function` / `Cannot read properties of null (reading 'Map')`）——遇到这类瞬时错误不再弹「初始化失败/渲染失败」给用户，而是自动重试（最多 6 次，避免死循环），稍后重绘即可；真正的业务异常（如坐标非法）仍会正常提示；
   4）顺带：既然是瞬时错误，失败时也不再要求用户手动刷新；配置端地图「初始化失败」的提示同样附上页面诊断信息，便于定位。
5. 考勤打卡：手机端地图——诊断信息直接显示在页面上 + 自动补载（绕开 document.write）：
   1）诊断信息放上页面：手机上打不开控制台，所以地图加载失败时，提示下方会直接渲染一段**诊断信息**（页面地址、来源 origin、AK 尾号、页面里的百度脚本标签、BMap/BMapGL 是否注册、百度报错原文、是否已尝试异步补载、是否 PWA 独立窗口、联网状态、api.map.baidu.com 是否可达、屏幕尺寸、UA），并提供**「复制诊断信息」按钮**（优先系统剪贴板，老 iOS 自动退回 execCommand），点一下复制后粘贴发给我们即可定位；
   2）**尝试自动修复**：`api?v=3.0` 返回的引导脚本内部是用 `document.write` 去加载真正的 getscript 的，而现代浏览器在「慢网络 + 跨域脚本」时会**忽略 document.write**（Chrome 的慢速网络干预），于是真正的 SDK 永远加载不出来、BMap 始终未定义——这正好解释「电脑端正常、手机端一直出不来」。现在等待约 5-6 秒仍未注册出 BMap 时，会自动改用**带 `callback` 参数的异步方式再补载一次**（百度据此走异步路径、不再依赖 document.write，并带时间戳避免拿到被缓存的失败响应）；
   3）同时保留上一版的能力：等待时间 15 秒（配置端 12 秒）、preconnect 预热、恢复联网/回到前台自动重试、`referrerpolicy="origin"` 统一 Referer 形态；
   4）若仍加载不出：诊断信息里的「api.map.baidu.com: 可以访问」说明不是网络问题 → 按提示核对 AK 的 Referer 白名单（白名单需含协议与端口、不支持端口泛匹配，手机端若用不同来源访问要把那个来源也加上，可临时填 `*` 验证）；若显示「访问失败」则更像手机网络/DNS 被拦，换网络再试。功能不受影响：打卡点仍会以文字列出，配置端可用「手填经纬度 + 半径」。
6. 考勤打卡：手机端地图加载失败——把「原因判断」做准 + 加快/加稳加载（含 Referer 白名单排查指引）：
   1）现象：电脑端地图正常，手机端（PWA 与手机浏览器）加载不出并提示「百度地图 AK 校验未通过」。此前该提示是**超时统一话术**——不管真实原因是「百度明确拒绝（白名单不匹配）」还是「脚本压根没加载出来（网络慢/被拦）」，都显示同一句，容易把人引到错误方向；
   2）现在会先判断再提示：① 若记录到百度的报错原文（如 `APP Referer校验失败`）→ 判定为 **AK/Referer 白名单问题**，并给出当前页面的完整地址（协议+域名+端口）、说明「百度浏览器端 AK 按 Referer 校验、白名单**不支持端口泛匹配**」，建议把该来源加入白名单或用 `*` 临时验证；② 若百度**没有**报错 → 判定为**网络/加载慢**（不再误报 AK 校验失败），提示可下拉刷新、切换网络再试，并说明「下方仍会列出全部打卡点，在任一点半径内可正常打卡」；
   3）同时把加载过程加稳：等待时间从 6 秒延长到 15 秒（配置端 4 秒→12 秒，手机慢网络下百度那条「引导脚本→getscript→模块」请求链本来就要几秒）；并新增 `<link rel="preconnect">` 预热百度域名、在**恢复联网**或页面回到前台时自动重试一次（成功即把降级提示换成真地图，无需用户手动刷新）；
   4）模板给百度脚本加了 `referrerpolicy="origin"`：强制所有浏览器/设备都只发送「源」（协议+域名+端口、不带路径与参数），避免个别手机浏览器（如较老 iOS）按默认策略发完整 URL 或干脆不发 Referer，导致与电脑端校验结果不一致；
   5）新增 `[考勤地图诊断]` 控制台输出（当前地址、AK 尾号、BMap 注册状态、是否 PWA 独立窗口、联网状态、百度报错原文，并探测 api.map.baidu.com 是否可达）：手机上若仍加载不出，把这几行发出来即可定位是「白名单来源不一致」还是「网络被拦」。

8. 企业聊天室：版本更新提示的「版本号 / 更新时间 / 操作按钮」改为置顶，彻底避免被长日志挤掉：
   1）现象：更新说明直接取自 VERSION_MESSAGE.txt，日志是「一行一个长段落」（一条几百字），而提示条高度有限、又不能滚动 —— 排在文字**后面**的「版本号、更新时间、立即更新按钮」被顶到屏幕外，用户看不到也点不到（在导出更新按钮之前那版仍是这样，因为按钮始终排在长文本之后）；
   2）修复思路（结构上根治，而不是继续调高度）：把提示条改成**上下两行** —— 第一行是「图标 + 标题 + 版本号 + 更新时间 + 操作按钮 + 关闭」，第二行才是更新说明（限高、可滚动）。这样无论日志多长，按钮永远在长文本**上面**；即使样式没加载出来，按 DOM 顺序按钮也排在长文本之前，依然可见可点；
   3）配套：更新说明折叠态预览截断为最多 2 行、每行 80 字（完整内容仍在「查看全部更新日志」里可展开滚动查看）；正文区限高 `min(38vh, 220px)`、窄屏 `min(32vh, 180px)` 并各自可滚动；
   4）之前几轮加的「四个操作（立即更新 / 稍后更新 / 不再提示 / 关闭）」「版本与时间必显示」「latest 字段缺失兜底」「按钮判空再绑定」全部保留。
9. 考勤打卡：修复手机端两块地图（打卡范围地图、考勤配置里的圈选地图）不能用手指拖动/缩放：
   1）根因：百度地图 JS API 3.0 在手机上其实是靠浏览器把触摸「合成鼠标事件」来实现拖动的，而 iOS 在手指持续拖动时**不会再合成 mousemove**，双指缩放又会被浏览器当成「缩放整个网页」抢走 —— 所以手指在地图上既拖不动也捏不动（桌面端用鼠标一直正常，所以这个问题一直没暴露）。此前只加了 CSS `touch-action:none` 和调用 `enableDragging/enablePinchToZoom` 并不够；
   2）改为**自己实现触摸手势**：单指拖动 = 平移（用 `pointToPixel/pixelToPoint` 按像素精确移动地图中心）、双指捏合 = 缩放（按两指间距比例换算级别，并跟随双指中点平移），同时注册非 passive 的 `touchmove` 调 `preventDefault()`、并拦掉 iOS 专用的 `gesturestart/gesturechange`，彻底不让浏览器把这段触摸当成滚动页面或缩放网页；
   3）为避免「两套逻辑叠加导致拖动变成两倍距离」，接管时会把百度自带的拖动/捏合关掉（`disableDragging` / `disablePinchToZoom`），并在自己的实现里补齐**鼠标拖动**，桌面端行为保持一致；双击缩放仍保留。另有一处附带收益：手机上百度自带拖动会屏蔽地图 click 事件，关掉拖动后「在地图上点击设定打卡点圆心」在手机上也能正常触发；
   4）安全兜底：只有在确实拿得到平移/缩放接口时才「接管」；拿不到就原样返回、保持百度自带行为（不会把桌面端原本能用的拖拽弄坏）。拖动/缩放刚结束的 0.4 秒内会忽略地图 click，避免拖完手指一抬就把打卡点圆心挪走；
   5）考勤页的 viewport 增加 `maximum-scale=1.0, user-scalable=no`，避免 iOS Safari 把双指缩放当成整页缩放（这是地图之外的最后一道保险）。

   2）每一行按钮都写了鼠标悬浮说明（如「10 分钟后再提醒我」「本版本不再提示（发布新版本后会重新提示）」），避免用户猜按钮含义；
   3）**重要修复**：旧实现在「发现新版本」时会把服务端版本号写进 localStorage，导致下一次比较就没有差异了 —— 于是「稍后更新 / 关闭」之后再也不会提示（按钮形同虚设），只有「立即更新」有效。现在只在**真正执行更新**或**检测到无更新**时才同步版本号，三个「不立即更新」的按钮因此都能按各自的语义生效；
   4）用户的选择会被记住：稍后更新/不再提示记在 localStorage（`update_prompt_prefs`），关闭记在 sessionStorage（仅当前页面会话）；用户点「立即更新」后这些记录会自动清除；
   5）强制更新（服务端 .env 配 `FORCE_UPDATE=true`）时仍然只给「立即更新」（5 秒后还会自动刷新），不提供忽略入口，保证关键更新不被跳过；
   6）样式：「稍后更新」为描边次要按钮、「不再提示」为更弱的文字按钮，与主按钮「立即更新」区分；按钮多时自动换行，窄屏下整行居中，便于点按。
11. 企业聊天室：修复「版本更新提示」横幅看不到版本号 / 更新时间 / 「立即更新」按钮的问题：
   1）现象与原因：横幅里的更新说明直接取自 VERSION_MESSAGE.txt，而日志是「一行一个长段落」（本期一条就有 300 多字）。横幅是 position:fixed 且既没有高度上限、也不能滚动，长文本把横幅撑得比屏幕还高，排在文字后面的「版本 / 更新时间 / 立即更新按钮」被顶出视口——fixed 元素超出视口的部分无法靠页面滚动看到，于是用户"看不到按钮、点不到、没法更新"（非强制更新时 30 秒后横幅还会自动消失，进一步加剧）；
   2）修复：①横幅加高度上限并自身可滚动（`max-height: min(80vh, 520px)` + `overflow-y:auto`），按钮永远不会被顶出屏幕；②折叠态的预览每条日志截断到 80 字（最多 2 条），并把「版本 / 更新时间」提到更新说明**之前**，不滚动就能看到关键信息；③展开后的完整日志高度也限制在 `min(28vh, 180px)` 内滚动；
   3）同时修掉两处健壮性问题：①原来 `updateInfo.latest.build_time` 一旦接口字段缺失，就会在模板字符串里直接抛错，导致**整条横幅根本不渲染**（用户彻底失去更新入口）——现在对 latest 做兜底，字段缺失只是少显示一行；②「立即更新」按钮改为先取元素、判空再绑定，避免个别情况下抛错导致横幅上所有按钮全部失效；
   4）样式细节：文字区允许收缩（`min-width:0`）并左对齐，操作按钮与关闭按钮独立成块、不参与文字区滚动；窄屏（≤768px）下文字与按钮各占一行、按钮加大更好点按；只让左侧大图标转圈（原来 `.update-content i` 会把按钮里的图标也一起转起来）；
   5）说明：需同步 static/js/chat.js 与 static/css/chat.css（版本号均为 `?v=20260917-update01`，chat.css 的 6 处模板引用已一并更新）。该横幅只在「服务端 STATIC_VERSION 与浏览器本地记录不一致」时出现，若要复现验证，可把 settings.py 的 `STATIC_VERSION` 改成新值并同步 chat.html 里的 `CURRENT_VERSION`。
